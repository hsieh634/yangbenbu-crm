# 養本簿 CRM：部署

> 版本：Phase 1（2026-11-19）

## 1. 映像

一個 `Dockerfile`，四個建置目標：

| 目標     | 內容                      | 用途                               |
| -------- | ------------------------- | ---------------------------------- |
| `api`    | NestJS API（port 4100）   | 正式環境                           |
| `worker` | pg-boss 背景工作          | 正式環境                           |
| `web`    | Next.js 前端（port 3100） | 正式環境                           |
| `demo`   | 以上三者 + 啟動時自動遷移 | 示範站：免費方案只有一個服務也能跑 |

```bash
docker build --target demo -t yangbenbu-demo .
```

```bash
docker build --target web --build-arg API_URL=http://api:4100 -t yangbenbu-web .
```

`API_URL` 是前端 `/api/*` 的轉發目的地，Next.js 在**建置時**寫入路由設定，所以分開部署時要在建置 `web` 時指定。`demo` 映像內部固定為 `127.0.0.1:4100`。

建置分成三段：`build`（含開發工具，編譯全部）、`prod-deps`（只裝正式環境套件）、`runtime`（正式套件 + 編譯產物，以 `node` 使用者執行）。Prisma CLI 保留在正式套件中，啟動時執行 `migrate deploy`。

`demo` 啟動順序（`scripts/demo-start.mjs`）：

1. `prisma migrate deploy`
2. 載入示範資料（可重複執行：已有資料時只補上今天起一週的預約）
3. 同時啟動 API、Worker、前端；任何一個結束，容器就結束，交給平台重新啟動

在本機用 Docker 跑完整示範站（不需安裝 Node.js）：

```bash
docker compose --profile demo up --build
```

## 2. 環境變數

| 變數                   | 服務              | 說明                                                                          |
| ---------------------- | ----------------- | ----------------------------------------------------------------------------- |
| `DATABASE_URL`         | api、worker、demo | PostgreSQL 連線字串。角色**不可**是超級使用者或具 BYPASSRLS（API 啟動時檢查） |
| `FIELD_ENCRYPTION_KEY` | api、worker、demo | 32 bytes 的 base64，欄位加密用                                                |
| `FIELD_HASH_KEY`       | api、worker、demo | 32 bytes 的 base64，與上面不同，身分證查詢雜湊用                              |
| `COOKIE_SECURE`        | api、demo         | HTTPS 環境設為 `true`                                                         |
| `REQUIRE_MFA`          | api、demo         | 正式環境設為 `true`                                                           |
| `DEMO_MODE`            | api、worker、demo | 示範站設為 `true`；**真實診所務必為 `false`**                                 |
| `WEB_ORIGIN`           | api               | 額外允許的前端來源；同源部署不必設定                                          |
| `PORT`                 | demo              | 對外 port，平台通常會自動提供                                                 |

`DEMO_MODE=true` 時：

- 登入頁顯示示範帳號
- Worker 每 10 分鐘補上未來一週的示範預約，並依現在時間推進今天的示範病患（報到 → 看診 → 療程 → 完成），訪客任何時候打開今日看板都有正在進行的就診。只會動到示範產生器建立、且沒有被訪客操作過的資料
- 停用「啟用兩步驟驗證」：示範帳號由所有訪客共用，有人啟用後其他人就無法登入

> 金鑰一旦設定就不能更換（更換後既有加密資料無法解密）。金鑰輪替工具列在 Phase 4。

## 3. 公開示範站：Render + Neon（免費）

作品集用的示範站，資料全部是虛構的，不受電子病歷境內存放的限制。

### 3.1 資料庫（Neon）

1. 在 [Neon](https://neon.tech) 建立專案，區域選 **AWS Asia Pacific (Singapore)**，離台灣最近
2. 複製連線字串（`postgresql://...?sslmode=require`）
3. 確認連線角色不會繞過 RLS：

```sql
SELECT rolname, rolsuper, rolbypassrls FROM pg_roles WHERE rolname = current_user;
```

兩個欄位都必須是 `f`。若不是，用 `scripts/init-db.sql` 的方式另外建立一個角色給應用程式使用。

### 3.2 服務（Render）

1. 將 repo 推到 GitHub
2. Render → **New → Blueprint**，選這個 repo；Render 會讀取 `render.yaml`
3. 填入 `DATABASE_URL`（Neon 的連線字串）；兩把金鑰由 Render 自動產生
4. 部署完成後開啟 `https://<服務名稱>.onrender.com`

免費方案閒置 15 分鐘會休眠，下次開啟需要約 30–60 秒喚醒。喚醒後 Worker 會立即補上這段期間的示範進度。

### 3.3 其他平台

`demo` 映像只需要一個 `DATABASE_URL` 與兩把金鑰，可以部署到任何能跑容器的平台（Fly.io、Railway、Koyeb、Google Cloud Run）。記憶體約 150–250 MB。

## 4. 正式環境（真實診所）

依[電子病歷製作及管理辦法](01-技術選型研究.md)，病歷資料與備份應存放在台灣境內：

| 元件     | 建議                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 前端     | Cloud Run（asia-east1 台灣），`web` 映像                               |
| API      | Cloud Run（asia-east1），`api` 映像，最少 1 個執行個體（看板即時同步） |
| Worker   | Cloud Run（asia-east1），`worker` 映像，固定 1 個執行個體              |
| 資料庫   | Cloud SQL for PostgreSQL（asia-east1），開啟時間點還原                 |
| 金鑰     | Secret Manager                                                         |
| 對外入口 | 同一個網域：`/` 到前端，`/api/*` 到 API（或由前端轉發）                |

上線前請完成[安全設計](03-安全設計.md)第 7 節的檢查清單。
